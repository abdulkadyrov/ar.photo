# Подготовка фото и видео

На `/create` у каждой пары есть кадрирование фото и редактор видео. Разница
пропорций более 1,5% вызывает предупреждение. Размеры в пикселях могут отличаться:
для наложения важны пропорции. Без ручного редактирования сохраняется прежнее
поведение AR — заполнение фотографии видео с центральной обрезкой, без искажения.

Форматы: оригинал, А4 (210:297 / 297:210), 9:16, 16:9, 4:5, 1:1, 3:4, 4:3,
2:3, 3:2, текущее соотношение второго файла. А4 задаёт пропорции, а не DPI печати.
Кадр перемещается мышью/пальцем и доступными с клавиатуры ползунками. Увеличение
1–4×. Изменения применяются явно, закрытие/отмена не меняют подготовленную пару.
Замена исходного файла сбрасывает относящиеся к нему настройки.

Монтаж хранит до 32 упорядоченных непересекающихся интервалов исходного видео.
Доступны разрез по курсору, выбор/удаление фрагмента, начало/конец по времени или
по курсору, отмена последних 50 изменений и восстановление исходного видео.
Минимальная длина фрагмента 0,1 секунды. Предпросмотр пропускает удалённые части.

Фото кадрируется локально и затем проходит обычную оптимизацию/удаление EXIF;
именно этот результат компилируется для распознавания. В редакторе можно скачать
PNG для печати. На экране готового проекта отображаются фактически обработанные
файлы и ссылки на подготовленные фотографии всех пар. Уже напечатанную фотографию
лучше не кадрировать: подгоняйте видео под её соотношение.

Видео при наличии изменений отправляется на сервер без локального перекодирования,
чтобы не потерять звук и точные исходные временные координаты. `metadata.edits`
содержит version=1, нормализованный crop и segments. Существующая цепочка
serverTranscodeRequired создаёт video_transcode; миграция БД не нужна. Worker
загружает настройки только у asset из job с совпадающими account/bucket/path,
проверяет числа, границы и реальную длительность через ffprobe, применяет crop,
trim/atrim, сбрасывает timestamps и соединяет оставшиеся части. На выходе H.264/AAC
либо H.264 без звука для немого оригинала. Нельзя передавать выражения FFmpeg через
настройки. Старые задания без edits проходят прежнюю обработку.

Релиз: worker нужно обновить до публикации интерфейса. Docker CI выполняет
`videoEditingCheck.js`: реальный FFmpeg, crop, сравнение кадров до/после вырезания,
точная длительность, проверка звуковых частот по обе стороны склейки, немой источник
и кадрирование без монтажа. Unit-тесты проверяют неверные настройки, а E2E —
согласование форматов, удаление/отмену, скачивание и замену файла на 390/1280px.
