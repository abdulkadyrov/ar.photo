# Воспроизводимая проверка AR

Стенд предназначен для инженерной проверки геометрии и трекинга. Он не заменяет
проверку камеры, автофокуса, бликов, нагрева и скорости Safari на физическом iPhone.

## Запуск

Использовать Node 22 и установленные зависимости проекта:

```sh
npm run dev:ar-lab
```

Открыть `http://127.0.0.1:4193/ar.photo/tools/ar-lab/`. Нажать запуск распознавания.
Ползунки изменяют наклон, поворот, расстояние и перекрытие открытки; можно выбрать
локальное видео. Файл остаётся в браузере, загрузки на сервер нет.

Отдельный HTML подключается только через локальный Vite. Он не включён в публичные
маршруты или основной production bundle. Никакие опубликованные QR не меняются.

## Что проверяется

- Three.js рисует открытку в перспективе в отдельный canvas виртуальной камеры.
- Настоящий MindAR получает только пиксели этого canvas и заранее скомпилированный
  эталон. Он не получает точных координат макета.
- Рабочие `installPlanarObservations` и `createPlanarAnchor` вычисляют наложение.
- Видео рисуется отдельным слоем и не попадает обратно во вход распознавания.
- Точное положение макета сохраняется в момент чтения входного кадра. Поэтому
  ошибка не сравнивается с более поздним положением камеры во время окончания расчёта.

Зелёный контур обозначает истинное положение макета, фиолетовый — найденное.
Ошибка углов измеряется в пикселях входной камеры, а не скриншота браузера.
`visibleFraction` — доля отрисованных кадров с наложением, не доля реального времени.
Участки без наложения учитываются отдельно: отсутствие измерений не считается
нулевой ошибкой или успешной стабилизацией.

## Автоматический прогон

При работающем локальном сервере:

```sh
node scripts/ar-lab-benchmark.mjs
```

Результаты и скриншоты записываются в игнорируемый Git каталог `artifacts/ar-lab`.
Переменные `AR_LAB_SCENARIOS`, `AR_LAB_DURATION_MS`, `AR_LAB_OUTPUT` и `AR_LAB_URL`
меняют сценарии, длительность измерения, каталог и адрес стенда.
`AR_LAB_BASELINE` задаёт SHA исходной версии (по умолчанию `0846a3a`).
`AR_LAB_NOISE=5 AR_LAB_DEFOCUS=2` добавляет шум исходных пикселей и
расфокусировку. Сценарий `duplicate` показывает два одинаковых экземпляра рядом.
Эти искажения не подменяют координаты ответа трекера.

Режим `hand` сочетает мелкие колебания и медленный дрейф по нескольким осям.
`fast` повторяет быстрые проходы, остановки и развороты. Амплитуда 0–3× и
скорость 0.25–4× регулируются независимо; изменение скорости не сбрасывает фазу.
Это синтетические траектории, а не измеренная модель конкретной руки или камеры.
Высокочастотные колебания ограничены 12 Гц при пределе камеры 30 кадров/с.

```sh
AR_LAB_SCENARIOS=hand,fast AR_LAB_NOISE=5 AR_LAB_DEFOCUS=1 \
AR_LAB_MOTION_STRENGTH=2 AR_LAB_MOTION_SPEED=2 \
AR_LAB_OUTPUT=artifacts/ar-lab-fast npm run test:ar-lab
```

Один сохранённый поток найденных углов дополнительно пропускается через старый и
новый фильтры. Это сравнение фильтров по одинаковым данным, а не два независимых
запуска камеры. Видимость и ошибки живого наложения сохраняются отдельно.
Replay не воспроизводит полностью захват/потерю цели; сравнивать RMS следует вместе
с числом принятых результатов. Прогон после четырёхсекундного прогрева измеряет
устоявшийся режим и не подтверждает скорость первого запуска.

## Наблюдения по записи пользователя от 28 ноября

В записи Stories AR показывает устойчивое наложение на портрет, а KHANZAMA —
колебания границ видео на открытке Milka под углом. Эталоны и геометрия съёмки
разные: из этого нельзя получить численное преимущество одного алгоритма или
определить внутреннее устройство конкурента.
Успешный участок конкурента — примерно 8–16 секунд; KHANZAMA — 27–34 секунды.
До этого в записи есть поиск цели и переключение приложений, их нельзя включать
в сравнение устойчивости уже распознанной фотографии.

В фильтре KHANZAMA обнаружен воспроизводимый дефект: остаточная разница между
исходной оценкой и сглаженной рамкой считалась продолжающимся изменением формы.
Несколько одинаковых ошибочных оценок подряд открывали быстрый режим и вызывали
отложенный скачок. Проверка согласованного изменения теперь сравнивает соседние
исходные наблюдения. Регрессионный тест сначала проваливался на старой версии.

Быстрые развороты виртуальной камеры воспроизвели отдельный дефект: корректное
измерение отвергалось из-за отставания сглаженной рамки. Наложение удерживало старую
позицию с ошибкой 57–76 пикселей. Пять коротких записанных последовательностей
сохранены в `src/features/public-ar/__fixtures__/fast-motion.json`.
Проверка скачка теперь использует предыдущую исходную оценку. Для интервалов
50–120 мс разрешено ограниченное продолжение подтверждённого движения, если
измерение близко к предыдущей скорости. Прогноз не используется для рисования.
Защита от повреждённого угла, противоположного скачка и устаревания сохранена.
Сравнение replay отдельно считает ошибки удерживаемых рамок при отклонении
измерения — исключать их из RMS и объявлять улучшение было бы неверно.

Отдельный эксперимент показывает риск экстраполяции: признаки только в четверти
площади эталона могут дать большую ошибку дальних углов даже при малой ошибке
самих признаков. `estimateCornerUncertainty` добавлена для диагностики; она не
меняет условия распознавания в рабочем просмотрщике. Порог нельзя выбирать только
по искусственному шуму, иначе можно лишить реальную открытку возможности распознаться.
