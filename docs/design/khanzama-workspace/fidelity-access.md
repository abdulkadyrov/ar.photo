# Вход и публичные документы: визуальная сверка

Проверены семь листов: `access-login`, `access-register`, `access-reset`,
`access-password`, `access-mfa`, `viewer-privacy`, `viewer-not-found`.
AR-камера, публичная работа и неподдерживаемый браузер проверены отдельно в
`fidelity-media.md`. Вместе это все десять листов доступа и публичного просмотра.

Размеры исходных панелей измерены по вертикальным/горизонтальным границам растра,
без заголовка листа; координаты находятся в `audit/access.bounds.json`.
Погрешность границы около 2 px. Для каждого листа сняты ПК и телефон с теми же
размерами viewport и DPR=1. Дополнительно проверены ширины 319 и 390 px.
Горизонтального переполнения нет.

До: `/tmp/khanzama-fidelity/access/before/`, чистый исходный коммит `76a8747`,
отдельный временный сервер 4180. После: `/tmp/khanzama-fidelity/access/after/`,
общий сервер проверки 4179. До отдельного экрана MFA не было: снимок «до» показывает
существовавшее подтверждение в настройках безопасности. После используется `/mfa`.

Изменены геометрия форм, размеры заголовков, структура регистрации и требований
к паролю, экран второго фактора, карточки конфиденциальности и 404. Имя из
регистрации передаётся в существующую серверную регистрацию как `full_name`;
эти отображаемые данные не используются для выдачи прав.

Смена пароля показывает подтверждение MFA только при реальной ошибке
`insufficient_aal`. Во время подтверждения значения формы сохраняются в памяти
компонента; пароль не сохраняется в localStorage. Модульный тест проверяет
полный путь: пароль → требование MFA → проверка фактора → сохранённый ввод →
успешное сохранение. Для снимка этого состояния изолированный demo fixture
возвращает ту же ошибку через локальный адаптер. Это не проверка действующего
аккаунта или реальной отправки письма.

Существенные отличия от иллюстраций сохранены намеренно:

- Рабочий сервер пока не отправляет письма восстановления. При отключённой
  доставке показывается честное объяснение, а не обещание отправленного письма.
- Нет выдуманных адресов поддержки и пользовательского соглашения. Ссылки ведут
  в существующие разделы; согласие касается права на загружаемые материалы.
- Подтверждение MFA и сохранение блокируются до допустимого состояния формы.
- 404 и privacy не копируют иллюстративные email. Контактный путь — поддержка.
- Копия интерфейса и длина текста адаптированы к реальному поведению. Полное
  равенство каждого пикселя с генеративным PNG не заявляется.

Воспроизведение: `FIDELITY_PHASE=after npx playwright test --config
docs/design/khanzama-workspace/audit/access.config.ts` при запущенном demo Vite 4179.

Общий каталог: `python3 docs/design/khanzama-workspace/audit/build-gallery.py`.
Он проверяет наличие всех 184 снимков «до/после» и точное равенство их размеров
с размерами 92 вырезанных исходных панелей. Результат находится в
`artifacts/design-fidelity/index.html`, исходные PNG не изменяются.
