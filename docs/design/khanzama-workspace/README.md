# Каталог постраничных макетов KHANZAMA

Открыть `index.html` — каталог листов с поиском и фильтрами по ролям. Каждый PNG
содержит одну страницу, ПК слева и телефон справа. Всего в плане 46 листов:
16 для администратора платформы, 20 для своего кабинета/CRM, 10 для входа и AR.

- `ROLES.md` — уточнение ролей по запросу владельца.
- `PAGE_REVIEW.md` — последовательный проход страниц и правила поведения.
- `SPEC.md` — ТЗ и этапы реализации.
- `pages.json` — названия, назначение и готовность каждого отдельного листа.
- `pages/` — сами PNG, разделённые на admin/account/access.
- `concept.png` — первая общая концепция; отдельные листы уточняют её.

Генеративные изображения — проектные макеты с демонстрационными данными. Любые
случайные подписи/числа внутри картинки не переопределяют роли и функциональные
правила. Ни новые экраны, ни новые разрешения не публикуются этим каталогом.

При добавлении листов `register_mockup.py ID SOURCE` сохраняет оригинал и
обновляет каталог. Для пересборки индекса: `python3 build_gallery.py`.
Для локального просмотра:

```sh
python3 -m http.server 8766 --bind 127.0.0.1 --directory docs/design/khanzama-workspace
```

## Реализация интерфейса

Рабочая версия использует две независимые оболочки: `/admin?section=overview`
для платформы и `/dashboard` для кабинета. CRM использует тот же кабинет;
безлимит определяется пакетом, доступ к администрированию — отдельно сервером.
Правила совместной работы агентов записаны в корневом `AGENTS.md`.

Администрация включает обзор, аккаунты и пользователей с карточками/редакторами,
подписки, тарифы и дополнения с предварительным просмотром назначения, аналитику,
активность, контент, обработку, хранилище, настройки и журнал. Кабинет включает
проекты/группы, AR-фото, создание/редактирование, медиа, QR и печать, статистику
своих работ, пакет, команду, профиль, настройки, безопасность и поддержку.
Вход, восстановление и публичный просмотр используют тот же светлый стиль.

Отсутствующие серверные возможности отображаются явно: глобальная история
сеансов и измеренное активное время, полная очередь обработки, физическая
ёмкость/состояние VPS и S3, резервные копии, административный просмотр чужих
приватных медиа, чат/заявки поддержки, управление удалёнными сеансами и загрузка
аватара. Эти экраны не подставляют показатели из макетов и не имитируют
сохранение неподдерживаемых операций. Контакт поддержки показывается только при
настроенном `VITE_SUPPORT_EMAIL`. Предпочтения уведомлений сохраняются; отдельный
сервис их доставки пока не подключён.

Проверки покрывают расходуемые добавления, сохранение профилей и настроек,
конкурентное сохранение, изоляцию кеша при смене пользователя, возврат с фильтрами,
загрузку/публикацию/просмотр/QR, печать и адаптацию кабинета на 319/768/1440 px.
Конкретные результаты последнего прогона и статус публикации указываются
отдельно в описании изменения; наличие PNG не означает успешного внедрения.
