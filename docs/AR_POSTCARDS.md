# AR-открытки: учёт тиражей и дальнейшая активация

## Подтверждённый продукт

Готовая открытка 100 × 150 мм с иллюстрацией, цитатой и небольшим QR.
Шесть начальных тем: Новый год, Ид аль-Фитр, 8 Марта, осенний бал,
день рождения лучшей подруги, день рождения друга/брата VIP.
Покупатель впоследствии добавляет своё видео: на всю открытку или в окно рамки.
QR открывает страницу конкретного экземпляра; изображение открытки остаётся AR-маркером.

Решение владельца от 25 ноября 2026: **один общий секретный код на магазин**
для всех переданных ему открыток. Код выдаётся на отдельном вкладыше,
не включается в QR, публичные данные экземпляра и выгрузку учёта.
У каждого экземпляра собственный публичный идентификатор и своё видео.
Магазин не получает роль администратора платформы.

## Реализованный первый этап

Раздел `/postcards` в кабинете аккаунта, доступный также через мобильное меню разделов.

- Магазин: название, адрес, отдельный общий код из 12 шестнадцатеричных символов.
  Код видят только владелец/управляющий с действующим правом записи; просмотр аудируется.
- Тираж: тема, название, 1–500 экземпляров. Создание резервирует экземпляры,
  но не создаёт AR-работу и не расходует добавление фото.
- Каждый экземпляр: UUID, полный учётный номер `PC-…`, номер внутри тиража,
  магазин, отметка продажи, отдельные поля будущей активации и AR-работы.
- Передача со склада, отметка продажи и возврат непроданных экземпляров на склад.
  После возврата их можно передать другому магазину, сохраняя историю.
- Выбор экземпляров вручную либо вводом полного номера со сканера клавиатурного типа.
  Это **не сканирование камерой телефона**, оно пока не подключено.
- Продажа и возврат требуют подтверждения. Вся выбранная группа проводится атомарно.
- Повтор сетевого запроса с тем же request ID не создаёт повторную операцию.
- Общие показатели выбранного магазина по всем тиражам: передано всего, продано,
  текущий остаток, возвращено. Повторная выдача после возврата — новая передача.
- Список последних 100 тиражей, до 500 экземпляров выбранного тиража,
  история последних 50 операций. В первом этапе список магазинов ограничен 1000;
  до расширения лимита необходима серверная пагинация.
- CSV выбранного тиража с номерами учёта и состояниями, без секретов.
- Реальный сервер: Supabase RPC + RLS. При отсутствующей миграции выводится ошибка,
  подмена локальными данными запрещена. Отдельный явный demo использует localStorage
  и помечает это на экране; это не облачное сохранение.

Миграция: `supabase/migrations/20261124211944_postcard_inventory.sql`.
Прямые записи в таблицы из клиента запрещены. Чтение ограничено аккаунтом.
Платформенная роль не выводится из пакета. Используются существующие проверки
прав аккаунта, активности пакета и существующие требования MFA.
Секреты находятся в private-таблице без SELECT для пользовательских ролей;
привилегированный RPC возвращает код после проверки прав и записи аудита.
Коды сохраняются для повторной выдачи вкладышей, поэтому они не только хешируются.
Ограничить доступ к резервным копиям секретов наравне с остальными credentials.

## Следующий этап: покупатель и AR

Этот этап **ещё не реализован**, публичные QR для тиража пока не выпускаются.
Существующие QR AR-работ не меняются.

1. Стабильный URL конкретного экземпляра открывает публичную страницу,
   не раскрывая магазин, его секрет или чужое видео до публикации.
2. Покупатель вводит общий код текущего магазина. До открытого доступа к проверке
   обязательны серверное ограничение попыток и одинаковые ошибки для неверного
   кода/неизвестного экземпляра; проверки только в браузере недостаточно.
3. Код проверяется исключительно для магазина, которому передан этот экземпляр.
   Если открытку вернули и передали другому магазину, действует код нового магазина.
   Активация после передачи не является автоматической отметкой продажи.
4. Сервер атомарно закрепляет открытку за защищённой сессией покупателя.
   Общий магазинный код никогда не даёт права перезаписать уже закреплённую открытку.
   Доступ для последующего редактирования — отдельный приватный механизм восстановления,
   не общий код магазина. Покупатель не становится участником студийного аккаунта.
5. Создание AR-работы на аккаунте издателя проходит существующий учёт добавлений,
   загрузку с ограничениями, обработку видео, создание маркера и подписанные URL.
   Новое добавление тратится один раз при создании работы; повтор, редактирование,
   удаление и исправление не меняют это правило. Для тиражей нужен отдельный показ
   будущей потребности в добавлениях и проверка наличия пакета при активации.
6. Пользователь видит предпросмотр кадрирования/вписывания и подтверждает публикацию.
   Настройки области видео хранятся в версии шаблона как нормализованные координаты
   прямоугольника, не меняют математику трекинга. Геометрия, маски и мобильно-снятое
   вертикальное видео требуют отдельной проверки в настоящем AR-просмотрщике.
7. После публикации тот же QR открывает существующий просмотрщик без регистрации.
   Сначала разрешается конкретный экземпляр, затем его видео; общий маркер
   иллюстрации не должен смешивать видео разных физических открыток.

Нельзя возвращать/передавать активированный экземпляр как новый. При этом отметку
реальной продажи допустимо внести после активации: эти события независимы.
Вопросы следующего этапа: срок хранения видео, восстановление доступа покупателя,
пределы файла и правила удаления/модерации. Цены и выручка не выдумываются.

## Печать

Сгенерированные ранее картинки — визуальные эскизы с ненастоящими QR, не печатные
мастера. Нужно разделить иллюстрацию, надписи, рамку и место реального QR,
утвердить геометрию окна и версии шаблонов. Затем выпускать файлы 100 × 150 мм
с проверенными отступами/вылетами и уникальными QR, а общий код магазина —
на отдельном вкладыше. Пробная печать и AR-тест на физической открытке обязательны
до большого тиража.

## Проверка

Node 22.22.2. Изолированный SQL-тест исполняет миграцию в PGlite (PostgreSQL WASM),
с фикстурами аккаунтов и вспомогательных функций доступа. Он проверяет реальное
выполнение SQL/RLS/RPC, но не заменяет тест всей Supabase-схемы, Auth, MFA или живого API.
Временная установка тестового движка не меняет зависимости приложения:

```sh
npm install --prefix tmp/postcard-tooling --no-package-lock --no-audit --no-fund @electric-sql/pglite@0.3.14
PGLITE_MODULE_PATH="$PWD/tmp/postcard-tooling/node_modules/@electric-sql/pglite/dist/index.js" node tests/database/postcards.integration.mjs
npm run check
```

`tests/e2e/postcards.spec.ts` проверяет demo-сценарий учёта при 319/390/1440px.
Browser demo не доказывает работу облачного API или камеры на физическом телефоне.
Применение миграции к удалённой базе и публикация фиксируются отдельно от локальных проверок.
